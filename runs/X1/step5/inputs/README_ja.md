# CCS26 Step 5 — セッション・多重度・名前の追加対照

Step 4 で同定された変更は、特定の閉項を取得時に等値照合するものだった。ここでは、同じ未修正版・候補版を使い、別の条件だけを動かす診断を3モデルで行う。Step 4 の集計は `STEP4_RESULTS.md` と `step4_results.tsv` に記録した。

| モデル | 到達する事前期待 | 到達不能の事前期待 |
|---|---|---|
| `session_join` | 同じ新鮮なセッション識別子で2つの前提をそろえる | 異なるセッションにしか存在しない2つの前提を1規則で結合する |
| `linear_pair` | 内容が等しい2つの線形事実を1回の規則発火で消費する | 線形事実が1つだけの枝で、同じ事実を1回の規則発火の2つの前提に使う |
| `name_constructor` | `q0/0` と引用公開名 `'q0'` をそれぞれ正しい場所で取得する | 反対側の値を構成子として、または公開名として取得する |

期待値と入力ハッシュは実行前に `cases.json` に固定した。すべて既知の初期化からの到達性を問う小モデルで、8補題を2版で実行する。未修正版の翻訳後の結果は実測として記録する。候補版では、正例4件の到達、負例4件の到達不能を、Tamarin の直接検証結果と対にして検査する。

## WSL で実行する

ZIPを展開し、`ccs26_step5_20261115` ディレクトリから実行する。移動済みの場合は実際のパスを指定する。

```bash
CCS3_RUN="$HOME/ccs26-step3.GmwNrdN0/ccs26_step3_20261115/step3-build.QWLTTEqu"
CCS4_ARCHIVE="$HOME/ccs26-step4.UjFj3rE8/ccs26_step4_20261115/step4-run.ncOKnsi9/evidence.tar.gz"

sha256sum -c SHA256SUMS &&
bash run-step5.sh "$CCS3_RUN" "$CCS4_ARCHIVE"
```

Step 4 アーカイブのハッシュと、そこに記録したTamarinバイナリ2本のハッシュを照合する。Step 4 と同じ固定イメージ上で、1 CPU・2 GiB、各コマンド60秒、ネットワーク無効の条件で実行する。新しいビルドやイメージ取得は工程に含まれない。

## 結果の読み方

- `stage=complete`、`rc=0` は両版について8件ずつの観測を記録したことを示す。
- `MATCH` は直接検証と翻訳後の判定が一致した行。候補版が8件すべて `MATCH` なら、この追加対照で定めた期待を満たす。
- `DIFFERENT` は判定の差。特に `linear_pair` の負例に差が残れば、同じ規則内での線形事実の扱いを生成PVとトレースから確認する。
- `REVIEW` は判定不能、実行結果の不足、事前期待とのずれ、または翻訳警告・制約等の生成差がある行。原ログを参照して解釈する。

終端に出る `ARCHIVE=` が指すファイルと SHA-256 を共有する。アーカイブの `baseline/`、`candidate/` に補題別の表と原ログ、候補版側に生成差分がある。

配布前の確認は、ファイルハッシュ、スクリプト構文、過去実測の出力形式での判定処理、模擬Dockerでの収録経路。今回の新規モデルを実際のTamarinとProVerifで評価した結果は未取得。
